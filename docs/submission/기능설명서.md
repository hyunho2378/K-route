# K-Route 기능설명서

> 2026 관광데이터 활용 공모전(웹·앱 구현 부문) 지정과제 3 · 해시태그 #덕질투어 #다국어 #로컬관광 #여행플래너 (+RAG 챗봇)
> 서비스 한 줄: **K-콘텐츠의 원조 도시 춘천을, 게임처럼 고르고 지도로 걷는다.**
> 심사 경로: `/gts/quiz` → `/gts/build` → `/gts/route` → `/gts/go`, K-가이드 챗봇은 build부터 상주.

---

## 1. #덕질투어 · 취향으로 고르는 K-콘텐츠 코스

**문제.** 한류 여행이 수도권에 쏠려 있다. 춘천에 와도 "어디가 K-콘텐츠 장소인지" 알 수 없다.

**기능.**
- 40초 설문 5문항(끌린 콘텐츠 · 여행 성향 · 동행 · 체류 · 이동 수단). 탭하면 바로 다음 문항으로 넘어간다.
- 결과 = 여행 타입 배지 4종(Frame Hunter / Local Taster / Lakeside Walker / Cafe Hopper) + 추천 장소.
- 추천은 **결정론 점수**다. 콘텐츠 일치 +5(앵커) / +2(연계), 성향 +3, 동행 +1, 이동 제약 -2. 동점은 공사 집중률이 낮은 곳이 위로.
- K배지는 **근거가 강한 곳에만** 붙는다. `SOURCE_SPOTS.md`의 근거 강도가 약하거나 없으면 배지 없이 일반 장소로만 노출한다.
  - 예: 공지천은 '겨울연가 촬영지'로 표기하지 않는다(촬영 근거 없음). 레고랜드는 덴마크 IP라 K-콘텐츠로 분류하지 않는다.
- NFC 스탬프(최소 데모): 앵커 현장의 스티커를 찍으면 갈래별 배지가 쌓이고, 다 모으면 다국어 인증서 이미지를 저장한다.

**화면.** `/gts/quiz` · `/gts/build` · `/stamp/:spotId/:t`

## 2. #다국어 · 공사 다국어 데이터 + 3언어 UI

**기능.**
- UI 3언어(한국어 · English · ไทย). 전환해도 레이아웃이 밀리지 않는다(두 언어를 같은 칸에 겹쳐 그린다). 사전 키 1,342개 3언어 동형.
- 장소 정보는 공사 **국문(KorService2) · 영문(EngService2)** 원문을 그대로 받아 쓴다. 영문 항목이 있으면 영어 화면에 영문 이름·소개가 나온다.
- 태국어는 공사가 제공하지 않는다. 챗봇이 한국어·영어 원문을 읽고 **태국어로 답한다**(LLM 번역).

**화면.** 전 화면 · 챗봇

## 3. #로컬관광 · 공사 연관 관광지로 잇는 로컬

**기능.**
- 하이브리드 풀 206곳 = 공사 춘천 관광지 162곳 + 공사 목록에 없는 로컬 맛집·카페 44곳.
- 같은 장소가 양쪽에 있으면 하나로 합치고 검증 태그를 물려준다.
- 공사 **연관 관광지 API**로 "이 장소 방문객이 함께 많이 찾은 곳"을 챗봇 지식에 넣는다.
- 공사 **집중률 API**로 "지금 가면 여유 / 보통 / 혼잡"을 카드와 지도에 붙인다. 경계는 춘천 1,800행 분포의 3분위(32.15 / 61.16).

**화면.** `/gts/build` · `/gts/route` · `/gts/go`

## 4. #여행플래너 · 담고, 지도로 보고, 실제로 출발

**기능.**
- 담기: 정원(반나절 3곳 · 하루 4곳)만큼 고른다. 고른 순서가 방문 순서다. 카드에 대표이미지·K배지·추천 사유·집중률.
- 지도: 번호 핀과 선이 그려지고, 왼쪽 타임라인에 장소·배지·집중률이 선다.
- 출발: 현위치(동의 후)에서 첫 장소까지 도보·택시 예상 시간과 경로를 보여 준다. "다음 장소"로 이어 간다.
- 차량·결제는 심사 경로 밖의 부가 흐름으로 남겨 두었다(BM 근거).

**화면.** `/gts/build` · `/gts/route` · `/gts/go`

## 5. #RAG챗봇 · 공사 공식 데이터만 답하는 안내원

**기능.**
- 우하단 K-가이드 버튼 → 시트로 대화. 지금 고른 장소를 우선 근거로 삼는다.
- 지식베이스 `spot_chunks` = 공사 상세(소개·이용시간·요금·메뉴) + 연관 관광지 + 검증된 K-콘텐츠 태그. 오디오가이드(odii)는 일일 호출 한도 해제 후 같은 스크립트로 적재해 근거에 더한다.
- 공사 데이터에서 관련 근거를 검색(RAG)한 뒤 그 **근거 안에서만** 답을 생성한다. 인용할 근거가 없으면 **모델을 부르지 않고 "정보가 없습니다"로 끝낸다.** 지어내기를 구조로 막는다.
- 답변 아래에 **출처 장소 칩**이 붙고, 누르면 그 장소의 공사 원문 상세로 간다. 출처는 생성문이 아니라 검색된 청크에서 뽑으므로 항상 실제 근거를 가리킨다.
- 태국어 질문은 영어로 옮겨 영문 청크를 찾고 태국어로 답한다(공사 데이터에 태국어가 없음).
- 생성기는 운영 환경에서 공사 데이터를 근거로 답을 만든다(Gemini). **생성기가 없거나 장애면 지어내지 않고 검색된 공사 원문을 출처째 그대로 반환하는 안전 모드로 자동 강등한다**(근거 밖 문장 0). 무환각을 두 겹으로 보장한다.

**화면.** `/gts/build` · `/gts/route` · `/gts/go` 우하단 FAB

## 6. 기능 → 화면 → 공사 OpenAPI 매핑

| 기능 | 화면 | 공사 OpenAPI | 비고 |
|---|---|---|---|
| 취향 설문·추천 | `/gts/quiz` | 국문 목록 · 연관 관광지 · 집중률 | 추천은 LLM 없이도 동작(결정론) |
| 코스 담기 | `/gts/build` | 국문·영문 목록/상세/사진 · 집중률 | 카드·상세 원문 |
| 장소 상세 | `/gts/build` | 국문·영문 상세 · 오디오가이드(odii) | 장소명 완전일치 테마만 |
| 지도 동선 | `/gts/route` | 국문 목록 · 집중률 | 번호 핀·타임라인 |
| 출발 안내 | `/gts/go` | 국문 목록 · 집중률 | 교통은 국토부 TAGO |
| K-가이드 챗봇 | build·route·go | 국문·영문 상세 · 연관 관광지 · 오디오가이드 | `spot_chunks` 근거 · 생성 Gemini |
| NFC 스탬프 | `/stamp/:spotId/:t` | (공사 API 아님 · 검증 태그 기반) | 앵커 13곳 |

상세 근거와 오퍼레이션별 사용처는 `docs/submission/공사API_사용처.md`.

## 7. 지키는 규율

- 근거 없는 성지 주장 금지. 근거 강도까지 기록해 두고, 약한 곳에는 배지를 붙이지 않는다.
- 공사 API는 실호출로 확인한 오퍼레이션만 쓴다. 지역코드도 코드조회 API로 매칭한다(하드코딩 없음).
- 응답 원문은 가공 없이 저장한다. 화면에 쓸 때만 태그를 푼다.
- 브라우저 저장소를 쓰지 않는다(로그인은 httpOnly 쿠키).
